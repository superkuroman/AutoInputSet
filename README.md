# GameAutomation

GameAutomation 是一套讓使用者「示範一次操作，再讓電腦重複執行」的 Windows 遊戲自動化工具。

它的目標不是要求使用者寫程式，而是把遊戲中的操作整理成容易理解的步驟，例如：

```text
等待主畫面出現
→ 點擊每日任務
→ 等待領取按鈕出現
→ 點擊領取
→ 等待完成畫面
```

完成後，使用者只需要選擇一份流程並按下執行，GameAutomation 就會按照保存的步驟操作遊戲。

> 目前仍在開發中，尚未具備完整的自動執行能力。現階段已經可以選擇遊戲視窗、擷取畫面及查看畫面座標。

## 它想解決什麼問題？

許多遊戲每天都有固定但重複的操作：

- 開啟每日獎勵頁面
- 點擊簽到
- 領取任務獎勵
- 重複進入固定選單
- 等待某個畫面出現後繼續操作

一般的連點程式只知道「在固定時間點擊固定位置」。只要遊戲載入比較慢、解析度改變或視窗移動，就可能點錯地方。

GameAutomation 的方向是同時使用：

- 相對位置：記住按鈕在遊戲畫面中的比例位置
- 畫面辨識：先確認指定圖案或按鈕出現
- 步驟流程：按照使用者安排的順序執行

因此它最終應該能表達：

```text
看到什麼
→ 在哪裡操作
→ 接著等待什麼
→ 如果沒有出現要等多久
```

## 最終會怎麼使用？

整套工具分成三個程式。每個程式只負責一件容易理解的事情。

### 第一步：Capture 告訴系統「要看哪裡、按哪裡」

開啟：

```text
GameAutomation.Capture.exe
```

Capture 預定讓使用者：

1. 選擇正在執行的遊戲視窗。
2. 擷取遊戲畫面。
3. 在畫面上點選需要操作的位置。
4. 框選需要辨識的按鈕或圖案。
5. 為圖片命名，例如「主畫面」或「領取按鈕」。
6. 保存位置與圖片，供後續步驟使用。

簡單來說，Capture 負責收集自動化所需的素材。

```text
遊戲畫面
→ 點選按鈕位置
→ 框選辨識圖片
→ 保存成可使用的素材
```

### 第二步：Editor 告訴系統「操作順序」

開啟：

```text
GameAutomation.Editor.exe
```

Editor 預定讓使用者將操作排列成流程：

```text
01 等待圖片：主畫面
02 點擊位置：每日任務
03 等待 500 毫秒
04 等待圖片：領取按鈕
05 點擊圖片：領取按鈕
06 完成
```

使用者不需要撰寫程式，只需要新增、刪除、排序步驟，並從 Capture 保存的素材中選擇要使用的圖片或位置。

完成的流程會保存成一份 Script。不同遊戲、角色或用途可以建立不同 Script。

### 第三步：Runner 負責執行

開啟：

```text
GameAutomation.Runner.exe
```

Runner 預定讓使用者：

1. 選擇一份已完成的 Script。
2. 確認目標遊戲視窗。
3. 按下開始。
4. 查看目前執行到哪個步驟。
5. 必要時立即停止。

Runner 會等待正確畫面出現，再執行對應操作，而不是只依靠固定延遲一直點擊。

## 三個程式如何合作？

```text
Capture
收集圖片與座標
       ↓
Editor
將素材排列成操作流程
       ↓
Runner
讀取流程並操作遊戲
```

例如，要建立「每日簽到」流程：

1. 使用 Capture 擷取主畫面、簽到按鈕和領取按鈕。
2. 使用 Capture 記錄需要點擊的位置。
3. 使用 Editor 將等待與點擊步驟排好。
4. 將流程保存成「每日簽到」。
5. 以後開啟 Runner，選擇「每日簽到」並執行。

## 為什麼座標不直接記成 1453, 822？

GameAutomation 會將位置保存成畫面比例，例如：

```text
X = 0.7568
Y = 0.7611
```

這代表位置位於遊戲畫面寬度約 75.68%、高度約 76.11% 的地方。

這樣即使遊戲從 1920×1080 改成其他解析度，仍有機會點到相同的相對位置，不會被單一螢幕解析度綁死。

## 圖片、流程與紀錄放在哪裡？

發行資料夾預定保持簡單：

```text
GameAutomation/
├─ GameAutomation.Capture.exe
├─ GameAutomation.Editor.exe
├─ GameAutomation.Runner.exe
├─ Templates/     Capture 保存的辨識圖片
├─ Scripts/       Editor 保存的操作流程
└─ Logs/          Runner 的執行紀錄
```

### Templates

保存需要在遊戲畫面中尋找的圖片，例如：

```text
Templates/
├─ MainMenu.png
├─ DailyButton.png
└─ ClaimButton.png
```

### Scripts

保存已經編排好的操作流程，例如：

```text
Scripts/
├─ 每日簽到.json
└─ 領取每日獎勵.json
```

### Logs

保存 Runner 執行過程，方便知道成功、失敗或停在哪一步。

## 目前可以做什麼？

目前可以實際使用的是 Capture 的第一部分：

1. 啟動 `GameAutomation.Capture.exe`。
2. 從清單選擇遊戲視窗。
3. 按下「擷取畫面」。
4. 在擷取圖片上移動滑鼠。
5. 查看該位置的 Pixel 與 Normalized 座標。

目前各程式狀態：

| 程式 | 現在的狀態 |
|---|---|
| Capture | 可以選擇視窗、擷取畫面及查看座標 |
| Editor | 只能開啟空白視窗 |
| Runner | 只能啟動，尚不能執行流程 |

所以目前版本是技術原型，不是可供一般使用者完成自動化的正式版本。

## 接下來要完成什麼？

開發方向按照「每完成一階段，就多一段真正可用的流程」安排。

### 階段一：記住並重現點擊位置

```text
Capture 點選遊戲畫面
→ 保存位置
→ Runner 讀取位置
→ Runner 點擊遊戲中的相同位置
```

完成後，系統會第一次具備真正操作遊戲的能力。

### 階段二：保存一連串操作

```text
保存多個點擊與等待步驟
→ Runner 依序執行
→ 顯示執行進度
→ 可以安全停止
```

完成後，可以執行簡單但不具畫面判斷能力的流程。

### 階段三：辨識畫面後再操作

```text
Capture 框選按鈕圖片
→ Runner 在遊戲畫面尋找圖片
→ 找到後才繼續點擊
→ 找不到則等待或停止
```

完成後，流程不再完全依賴固定等待時間，可靠性會明顯提高。

### 階段四：讓一般使用者編輯流程

```text
Editor 新增步驟
→ 選擇圖片或座標
→ 調整順序與等待時間
→ 保存 Script
```

完成後，使用者不需要修改任何程式碼，就能建立自己的自動化流程。

## 使用時的重要觀念

- 自動化開始前，確認選擇的是正確遊戲視窗。
- 第一次執行新流程時，應在旁邊觀察並準備停止。
- 遊戲更新 UI 後，原本的 Template 圖片可能需要重新擷取。
- 不同遊戲可能禁止自動化工具；使用前應自行確認遊戲規則。
- 不應將帳號、密碼或其他敏感資料寫入 Script。
- 這套工具的方向是可觀察、可停止、可修改，而不是無法控制的背景連點器。
